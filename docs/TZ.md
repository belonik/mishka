## 1. Назначение и цели

### 1.1. Назначение

Приложение для ведения личных и рабочих заметок в формате Markdown с визуальным оформлением
уровня Bear: живые теги, аккуратная типографика, три колонки, мгновенный отклик.

### 1.2. Цели разработки

| ID | Цель |
| --- | --- |
| Ц-1 | Дать быстрый доступ к заметкам: от запуска до ввода текста — без диалогов и модальных окон |
| Ц-2 | Сохранить формат хранения открытым: обычные `.md`-файлы, читаемые любым редактором |
| Ц-3 | Обеспечить «живой» Markdown: разметка отображается по мере набора, а не в отдельном окне предпросмотра |
| Ц-4 | Не запирать данные: индекс восстановим, файлы можно открывать и вне приложения |
| Ц-5 | Дать возможность работать с файлами, лежащими в git-репозиториях и других папках, не копируя их |

### 1.3. Критерии успеха

- Пользователь ни разу не сталкивается с потерей текста при штатной работе и при аварийном завершении.
- Заметку можно открыть и отредактировать в любом стороннем редакторе без потери структуры.
- Ввод текста не имеет заметных задержек на заметках объёмом до 100 КБ.
- Заметка на 1000+ слов открывается и перерисовывается без рывков.

## 2. Термины и сокращения

| Термин | Значение |
| --- | --- |
| **Заметка** | Единица контента: текст в формате Markdown |
| **Хранилище (vault)** | Каталог, в котором приложение держит свои заметки, корзину и индекс |
| **Индекс** | `library.json` — метаданные заметок, которые нельзя выразить в Markdown |
| **Внешний файл (bound file)** | `.md`-файл вне хранилища, открытый приложением «на месте» |
| **Живая подсветка** | Отрисовка Markdown непосредственно в поле ввода, без режима предпросмотра |
| **Гуттер** | Левый отступ в редакторе, где рисуются маркеры списков и чекбоксы |
| **GFM** | GitHub Flavored Markdown — расширение с таблицами и списками задач |
| **ФТ / НФТ** | Функциональное / нефункциональное требование |

## 3. Границы проекта

### 3.1. Входит в объём

- Хранение и редактирование заметок в Markdown.
- Живая подсветка, таблицы, списки задач, теги.
- Три колонки: теги → список заметок → редактор/превью.
- Просмотр отрендеренного Markdown (WKWebView).
- Внешние файлы: открытие, правка на месте, история.
- Поиск, сортировка, корзина, экспорт.
- Темы оформления и типографика.

### 3.2. Сознательно не входит в объём

| ID | Что исключено | Обоснование |
| --- | --- | --- |
| И-1 | Синхронизация и облако | Пользователь синхронизирует папку сам (iCloud Drive, git, Syncthing) |
| И-2 | Мобильная версия | Проект нацелен на macOS; формат данных к переносу готов |
| И-3 | Шифрование заметок | Требует криптографического аудита; «блокировка» носит характер защиты от случайной правки |
| И-4 | Совместная работа | Однопользовательский инструмент |
| И-5 | Плагины и расширения | Ставка на предсказуемость и отсутствие зависимостей |
| И-6 | Песочница App Sandbox | Несовместима с правкой файлов в произвольных папках (см. НФТ-7) |
| И-7 | Локализация интерфейса | Интерфейс на английском, содержимое — на языке пользователя |

## 4. Пользователи и сценарии

| ID | Роль | Основной сценарий |
| --- | --- | --- |
| П-1 | Владелец заметок | Быстро записать мысль, найти её через месяц по тегу или слову |
| П-2 | Разработчик | Держать рабочие заметки и README рядом с кодом, править их на месте |
| П-3 | Читатель | Открыть чужой `.md` и прочитать его в удобной вёрстке |

**Ключевой сценарий 1 (ежедневный).** `⌘N` → набор текста → `#тег` → заметка автоматически
попадает в раздел тега. Через неделю поиск по слову находит её.

**Ключевой сценарий 2 (файл на месте).** `⌘O` → выбор `~/work/notes/report.md` → правка →
`⌃S` не нужен, сохраняется само → файл изменён там же, где лежал, копий не осталось.

**Ключевой сценарий 3 (чтение).** Файл открыт из Finder двойным щелчком → переключение в
режим «Preview» → читается как документ, ссылки открываются в браузере.

## 10. Ограничения и допущения

1. **Одно окно.** Многопользовательская работа с несколькими хранилищами одновременно не поддерживается: `Window`, а не `WindowGroup`, — сознательное решение, иначе каждое «открыть с помощью» плодит окно.
2. **Одно хранилище за сеанс.** Смена хранилища — только через параметр запуска.
3. **Отмена не переносится между заметками.** Переключение заметки заменяет буфер редактора.
4. **Корректность превью зависит от WebKit.** Различия версий WebKit могут влиять на вид таблиц и карточек.
5. **Индекс не является источником истины.** При расхождении приоритет у файлов на диске.
6. **Нет блокировки файла при редактировании.** Если файл правят снаружи в момент сохранения, побеждает последняя запись.
7. **Требуется macOS 15.** Используются `Window`, `.onChange(of:initial:)`, `SettingsLink`.
